# Purrcept 移动体验

本轮以 purrcept_go/main 为工作区。Purrcept Cel 提供品牌、状态语义和猫咪身份；
移动端扩展由 design/purrcept-cel.tokens.json 的 mobile 组明确持有，不改写共享
WebUI 的语法。用户已授权根据移动体验调整 Cel 约束。

## 参考与取舍

- [Material 3 Motion](https://m3.material.io/styles/motion)：界面位移采用可打断弹簧，
  保持手指操作和结果反馈的连续性，不把动画时长当作业务进度。
- [Duolingo 角色状态机](https://blog.duolingo.com/world-character-visemes/)：角色
  姿态由状态驱动，复用一个身体，而非在每个列表项放置独立装饰。
- [Headspace 品牌演进](https://italic-studio.com/projects/headspace-rebrand/)：用
  简洁插画、留白和明确文字降低第一次接触的负担。
- DSH Go 的欢迎页、ActivityStrip 和宠物驻足点是上游交互参考，可从 Git 历史查阅。其专有品牌
  美术不复制，继续使用 Purrcept 自有白猫，并以矢量绘制控制体积与动作。

## 移动端扩展

移动端的主要页面就是与主体相处的聊天空间。猫咪可位于首次引导舞台或聊天
的唯一实时状态区，这是对 Cel“仅 WebUI 首页展示”的明确调整；不会在每条
消息或每个设置项中重复出现。角色动作不能替代文字状态。

mobile 中的 hero 色是猫咪承载面，不编码运行状态；dark 色组支持系统深色。
毛色、阴影和腮红仅用于角色。更大的 panel/bubble/hero 圆角区别于桌面高密度
面板，内容宽度按移动阅读收束。空间位移采用同一组弹簧参数；颜色过渡仍为
120ms。主按钮和发送按钮以轻微按压与弹簧回弹回应手指；新消息仅首次进入时
做位移，刷新历史不重播。减少动效下保留静态姿势、状态文字和消息阶段，不持续眨眼或抖耳。

## 状态必须可证

配对前的连接失败按真实异常区分电脑不可达、超时、系统拒绝联网、证书日期、
指纹与 TLS 错误，不使用“连接中断、消息会补送”。原生只传稳定错误码，
不向 Flutter 交付异常原文或凭据。证书固定与有效期校验继续生效。

手机已保存、Engine 接管、前台接手、模型请求、行动执行和本次处理结束是
不同事实。Engine 的 engine.state 提供有限公开投影；界面不能根据发送耗时
假造思考，也不能把处理结束当作已经回复。断线时立即停止实时工作表现。
主体名字来自当前角色配置，只传名字，不传人格正文或模型密钥。

当 Engine 尚未提供状态、正在启动、断线或状态需要重新同步时，界面必须
如实给出文字和恢复路径，而不是无限显示“思考中”。


## 首次使用与权限

引导分为认识应用、准备电脑、扫码核对和可选权限四步，进度由原生 Room
保存。主操作固定在页底，长说明可以滚动，放大字体不会挤掉继续入口。
电脑端设置统一在 Engine WebUI 的「设备 → 连接安卓手机」。用户在同一页面
预览并保存 Phone 设置、显示和刷新二维码。配置更改正常重启后生效，邀请过期
直接刷新。Go 只承担手机端扫码、核对和连接，不要求用户编辑 TOML/JSON。

聊天无需无障碍或操控授权。通知只在明确点击后请求，拒绝后可从设备页进入
系统通知设置；手机操作需要单独启用无障碍和允许操控，主脑还需显式连接。
开启在线只启动可见前台服务，不自动恢复屏幕操控资格。

当前工作与消息处置分别呈现。点击消息状态可查看最近一次真实调用的有限
回执。短行动无需强制停留动画；全局忙碌区域及时回到实际阶段，历史回执仍
可供核对。深浅色和大字体预览由离线 widget 测试渲染，不代表真机权限已验收。
